# Резервная касса: установка и работа (версия 1.3)

Приложение для телефона. Когда касса магазина не работает или нет света, оно по штрихкоду показывает название и цену, считает чек и запоминает продажи, чтобы потом внести их в кассу вручную, и собирает отчёты по продажам за период. Работает без интернета.

## Что нового в версии 1.3

- **Сессия закрывается сама каждый день в 23:59** (по часам телефона), а не через 24 часа после первой продажи. Продажи после 23:59 попадают в новую сессию. Закрыть сессию вручную можно, как раньше.
- **Новая вкладка «Отчёты»** (кнопка справа внизу). Выберите период: «Сегодня», «Вчера», «7 дней», «Месяц» или «Период» (две даты). Приложение покажет:
  - **Итоги за период** одной таблицей: число чеков, сумма продаж, средний чек;
  - **Продажи по товарам**: товары в строках, а в столбцах сколько продано, себестоимость проданного, розничная сумма и **остаток товара**. Строки можно упорядочить: «Сначала крупные» или «По названию».

  Отменённые продажи в отчёты не входят. Закрыта сессия или нет, на отчёт это не влияет.
- **Остаток товара.** Приложение берёт его из прайса (столбец «Остаток» или «Количество остаток») и уменьшает с каждой продажей в приложении. Это «остаток по прайсу минус проданное здесь»: продажи в основной кассе магазина попадают в него только вместе с новым прайсом.
- **«Товары: цены и остаток»** (второй вид во вкладке «Отчёты», переключатель вверху). Найдите товар по названию, по штрихкоду (целиком или по последним цифрам) или камерой телефона (кнопка 📷) и измените **розничную цену**, **закупочную цену** и **остаток на складе**. То же открывается нажатием на строку товара в таблице продаж. Новая розничная цена сразу действует в чеке, закупочная цена и остаток сразу попадают в отчёт.
- **Закупочная цена и остаток из прайса.** Для себестоимости приложение теперь читает «Закупочную цену», а для остатка «Остаток». В выгрузке из учётной программы как есть (`prices.xlsx`) они читаются сами. В `prices.csv`, который делает `prep.html`, закупочных цен и остатков по умолчанию нет: чтобы они попали в файл, поставьте на странице галочки (часть 4, вариант Б). **Закупочные цены и остатки в файле на GitHub видны всем, у кого есть адрес сайта. А в самом телефоне они видны во вкладке «Отчёты» любому, в чьих руках телефон: пароля у приложения нет.**
- **Новый товар (его нет в прайсе):** в окне теперь два поля, «Розничная цена» и «Закупочная цена» (необязательная). Закупочная цена идёт в отчёт по себестоимости; с галочкой «Запомнить на этом телефоне» она запоминается вместе с товаром. Остаток такому товару можно вписать позже в «Товары: цены и остаток».
- **Товар, внесённый вручную, главнее товара из прайса.** Если штрихкод товара, внесённого вами вручную, совпал со штрихкодом товара из загруженного файла, в телефоне остаётся ваш товар, а товар из файла не загружается (целиком, со всеми его штрихкодами). Что не загружено, видно в ⚙ → «Последняя загрузка». Чтобы вернуть товар из файла, удалите свой товар в «Товары: цены и остаток».
- **Продажи хранятся 90 дней** (раньше 5): иначе отчёт за месяц был бы почти пустым. Срок можно изменить: `KEEP_DAYS` в начале файла `app.js`.
- **Одинаковый штрихкод у нескольких товаров.** Если штрихкод в прайсе стоит у двух и более товаров, при сканировании приложение показывает все эти товары, и кассир выбирает нужный. Это работает с версии 1.1; в версии 1.3 проверено заново (в том числе при вводе штрихкода руками и по последним цифрам).

## Что нового в версии 1.2

- **Прайс обновляется выгрузкой из учётной программы как есть.** Выгрузку (`.xlsx`) не нужно ни конвертировать, ни править: переименуйте её в `prices.xlsx`, загрузите на GitHub с компьютера, и телефоны сами её подхватят (часть 4, вариант А). Если `prices.xlsx` нет, приложение берёт `prices.csv`, как раньше.
- **Метка «демо-прайс».** Пока в приложении учебный список из 8 товаров, вверху жёлтая метка «демо-прайс», а в настройках подсказка, что делать. Так учебный прайс не спутать со своим.
- **⚙ → «Откуда прайс»:** видно, откуда взят прайс (`prices.xlsx`, `prices.csv`, свой адрес или файл с телефона).
- **Excel читается примерно в 10 раз быстрее и занимает меньше памяти.** Выгрузка на 4 тысячи строк (как ваша) разбирается за доли секунды.
- **В версии 1.2 закупочные цены и остатки в приложение не загружались** (с версии 1.3 загружаются, см. выше). Но если выгрузка лежит на GitHub, её видят все, у кого есть адрес (см. «Важно про приватность»). Тревожных всплывашек про это больше нет, в отчёте загрузки остаётся спокойная справка.

Что было добавлено в версии 1.1: чтение Excel с шапкой в несколько строк, страница `prep.html` (чистый `prices.csv`), выбор товара при одинаковом штрихкоде, запоминание номеров товаров на весах.

Вашего файла `prices.xlsx` в папке нет: это ваша выгрузка, её вы добавляете сами (часть 4).

## Часть 1. Выложить приложение в интернет (один раз, примерно 10 минут, с компьютера)

Нужен бесплатный аккаунт на GitHub. Приложению нужен адрес со знаком замка (https): без него камера не работает.

1. Откройте **github.com** и зарегистрируйтесь (Sign up).
2. Нажмите **«+»** вверху справа → **New repository**.
3. В поле Repository name впишите, например, `kassa` (лучше нейтральное имя, без названия магазина). Выберите **Public**. Нажмите **Create repository**.
4. На странице нового репозитория нажмите ссылку **«uploading an existing file»**.
5. Перетащите в окно **все файлы из этой папки** (папок создавать не нужно, все файлы лежат рядом).
6. Прокрутите вниз и нажмите **Commit changes**.
7. Вкладка **Settings** → слева **Pages** → в блоке Branch выберите **main**, папка **/ (root)** → **Save**.
8. Подождите 1–2 минуты и обновите страницу. Вверху появится адрес вида `https://ВАШ-ЛОГИН.github.io/kassa/`. Это адрес приложения.

**Важно про приватность.** У бесплатного аккаунта страница публичная: любой, кто знает адрес приложения, может открыть и скачать лежащий рядом файл прайса. Если вы кладёте туда выгрузку из учётной программы как есть (`prices.xlsx`), то видны будут и **остатки**, и **закупочные цены**. Остатки вы решили не скрывать. Закупочные цены решите отдельно: если их видеть нельзя, используйте вариант Б (часть 4) без галочки. Начиная с версии 1.3 закупочные цены нужны ещё и для отчёта по себестоимости, а остатки для столбца «Остаток»: без них в отчёте будет «—». Прежние версии файла остаются в истории изменений репозитория (вкладка Commits), даже если вы потом заменили файл. Убрать их оттуда непросто (проще всего удалить репозиторий и создать заново), а к тому моменту файл могли уже скачать. Адрес приложения никому не показывайте.

## Часть 2. Поставить на телефон

1. На телефоне откройте адрес приложения в **Chrome**. Интернет нужен сейчас и потом для обновления прайса.
2. Когда спросит про камеру, нажмите **«Разрешить»**.
3. Меню браузера (три точки) → **«Установить приложение»** (или «Добавить на главный экран»). На экране появится значок «Касса».
4. Откройте приложение с этого значка. Вверху должна быть зелёная точка и надпись вроде «прайс 06.11 15:30». Это значит, что прайс загрузился на телефон. Пока в приложении только учебный прайс, вместо этого будет жёлтая метка «демо-прайс»: так и должно быть до части 4.
5. **Проверка без сети:** выключите интернет на телефоне и откройте приложение ещё раз. Оно должно открыться и работать. Так будет и при отключении света.

## Часть 3. Проверка за 5 минут (с демо-прайсом)

1. Откройте `Тест_штрихкоды.png` на экране компьютера. Наведите камеру телефона на штрихкод молока. Должен прозвучать сигнал, а в чеке появиться «ДЕМО МОЛОКО», 95.
2. Наведите камеру на второй штрихкод молока: это тот же товар, поэтому количество станет 2.
3. Наведите камеру на три весовые этикетки. Суммы должны получиться **55,33**, **35,36** и **96,45**.
4. Нажмите **ПРОДАТЬ**. Чек очистится. 8 секунд можно нажать **«Вернуть»**.
5. Вкладка **«Сессия»**: видна сумма и список товаров. Нажмите **«По отдельности»**, чтобы увидеть каждый чек.
6. Нажмите **«Закрыть сессию»** и подтвердите. Вкладка **«История»**: сессия там.
7. Вкладка **«Отчёты»**, период **«Сегодня»**. Если вы сделали только то, что в пунктах 1–4, там будет: чеков **1**, сумма продаж **377,14**, средний чек **377,14**. Ниже таблица по товарам: «ДЕМО МОЛОКО» 2 шт, себестоимость 140, розница 190, остаток **38 шт** (в учебном прайсе было 40); рис, мука и макароны с весами (остаток риса **6,904 кг**); в строке «Итого» себестоимость **268,39** и розница **377,14**. Закупочные цены и остатки в учебном прайсе придуманные: это только проверка.
8. Вверху нажмите **«Товары: цены и остаток»**, впишите «молоко» и нажмите на найденный товар: розничная цена 95, закупочная 70, остаток 38. Закройте окно и нажмите **📷**: наведите камеру на штрихкод молока из `Тест_штрихкоды.png`, откроется тот же товар. Если что-то измените и сохраните, вернуть учебные значения можно кнопкой **«Вернуть значения из прайса»** в окне товара.

Если всё получилось, замените демо-прайс настоящим (часть 4). Эта проверка работает только пока в приложении учебный прайс.

## Часть 4. Настоящий прайс

### Вариант А (проще): выгрузка из учётной программы как есть

1. Выгрузите из учётной программы список товаров в Excel и сохраните как **`.xlsx`**: столбцы **Код, Номенклатура, Штрихкод, Единица измерения, Розничная цена**. Столбцы «Закупочная цена» и «Остаток» (в вашей выгрузке «Количество остаток») тоже читаются: из них приложение берёт себестоимость и остаток товара для отчётов. Если их нет, в отчёте будет «—», а остаток можно вписать вручную. Если программа сохраняет старый формат `.xls`, откройте файл в Excel и выберите «Сохранить как» → «Книга Excel (.xlsx)».
2. **Выгружайте весь ассортимент, а не только то, что есть на складе.** Если в выгрузку попали только товары с остатком, то товар, которого сейчас нет в наличии, приложение не найдёт («нет в прайсе»). Если в отчёте есть настройка вывода нулевых остатков, включите её.
3. Переименуйте файл в **`prices.xlsx`**: только маленькие латинские буквы, как здесь. В Windows включите показ расширений (Проводник → Вид → Показать → «Расширения имён файлов»), иначе легко получить `prices.xlsx.xlsx`.
4. На GitHub откройте репозиторий → **Add file** → **Upload files** → перетащите `prices.xlsx` → **Commit changes**. В следующий раз делайте так же: файл с тем же именем заменит прежний.
5. Через 1–2 минуты телефоны сами скачают новый прайс (пока приложение открыто и есть интернет; проверка каждые 30 минут). Сразу: **⚙ → «Обновить прайс»**.
6. Проверьте: **⚙ → «Откуда прайс»** показывает `prices.xlsx`, вверху больше нет метки «демо-прайс», а в блоке **«Последняя загрузка»** число товаров похоже на ваш ассортимент. Если там есть примеры проблем («Штрихкод у двух товаров», «Некорректных штрихкодов»), их лучше исправить в учётной программе.

Что полезно знать:
- Если на GitHub лежат оба файла, `prices.xlsx` и `prices.csv`, приложение берёт **`prices.xlsx`**. Учебный `prices.csv` можно оставить.
- Если загруженный `prices.xlsx` оказался повреждённым или не тем файлом, прайс на телефоне **не меняется**, а причина видна в ⚙ при нажатии «Обновить прайс». Подставлять `prices.csv` вместо испорченного `prices.xlsx` приложение не будет.
- Если в новом файле меньше половины товаров, чем в прежнем, он отклоняется (защита от случайной загрузки не того файла).
- Закупочные цены и остатки приложение читает (для отчётов) и хранит на телефоне. **В самом файле на GitHub они остаются видны всем** (см. «Важно про приватность»). Если их видеть нельзя, используйте вариант Б без галочек.
- Остаток в отчёте считается так: остаток из последнего прайса минус то, что продано в приложении после загрузки этого прайса. Продажи в основной кассе магазина приложение не видит, поэтому прайс с остатками стоит обновлять почаще.

### Вариант Б: чистый прайс (закупочные цены и остатки по желанию)

Нужен, если закупочные цены или остатки нельзя показывать посторонним. Если они нужны для отчётов, поставьте галочки (шаг 3).

1. Откройте файл **`prep.html`** двойным щелчком (лучше в Chrome или Edge). Нажмите **«Выбрать файл»** и выберите выгрузку.
2. Прочитайте результат. Сверху: сколько товаров и штрихкодов. Ниже цветные блоки: в них то, что не так в данных, и что с этим делать. Красный блок («Товары без цены») обязательно.
3. Нужны себестоимость и остаток в отчётах? Поставьте галочки **«Добавить закупочные цены в prices.csv»** и **«Добавить остатки в prices.csv»** (они появляются, если в выгрузке есть такие столбцы). Тогда эти данные будут в файле, и их увидит любой, у кого есть адрес сайта. Без галочек в файле только розничные цены: в отчёте себестоимость и остаток будут «—» (остаток можно вписать вручную).
4. Нажмите **«Скачать prices.csv»**. Если есть проблемы, можно скачать ещё и «Список проблем»: его удобно передать тому, кто правит учётную программу.
5. На GitHub: **Add file → Upload files** → `prices.csv` → **Commit changes**.
6. **Если раньше вы загружали `prices.xlsx`, удалите его:** откройте файл в репозитории → значок корзины → **Commit changes**. Иначе приложение продолжит брать старый `prices.xlsx`. Вспомните и про историю изменений (часть 1).

### Другие способы (если GitHub неудобен)

- **Файл с телефона:** ⚙ → «Загрузить файл прайса (Excel или CSV)». Подойдёт и выгрузка из учётной программы как есть (закупочные цены и остатки из неё тоже читаются). Без интернета, один телефон, разово. Файл остаётся только на телефоне. Но если на сайте приложения лежит свой прайс, при ближайшей проверке телефон возьмёт его, и загруженное с телефона заменится.
- **Google Таблица:** Файл → Поделиться → Опубликовать в интернете → формат CSV → скопируйте ссылку и вставьте в ⚙ → «Адрес файла прайса». Этот способ я не смог проверить заранее. Если прайс не загрузится, используйте GitHub.

## Часть 5. Работа, когда касса не работает

1. Откройте приложение. Наведите камеру на штрихкод: товар сам попадёт в чек. Тот же штрихкод ещё раз даёт +1. Количество можно менять кнопками **+/−** или вписать число.
2. **Штрихкод не читается:** впишите в строку название или последние цифры штрихкода и выберите товар из списка.
3. **Один штрихкод у двух и более товаров:** откроется окно «Какой это товар?» со всеми этими товарами и их ценами. Нажмите на тот товар, который у вас в руках. То же будет, если набрать такой штрихкод руками.
4. **Весовой товар:** наведите камеру на этикетку с весов, вес и сумма подставятся сами. Если этикетки нет, найдите товар по названию и впишите «Сумму» или «Вес»: второе пересчитается.
5. **Приложение не знает номер на весах** (так бывает в первый раз для каждого весового товара): в чеке появится жёлтая подсказка. Найдите товар по названию, вес подставится сам. Сверху появится вопрос «Номер 278 на весах — это …?». Нажмите **«Запомнить»**: в следующий раз эта этикетка распознается сама. Ошиблись: ⚙ → «Номера с весов, которые вы запомнили» → **✕** рядом с номером.
6. **Другая цена (акция):** нажмите на цену в строке и впишите новую. У строки появится отметка «цена изменена», она попадёт в отчёт отдельной строкой.
7. **Товара нет в прайсе:** приложение предложит ввести название, **розничную цену** и (по желанию) **закупочную цену**. Закупочная нужна для отчёта по себестоимости. Можно запомнить на этом телефоне: в следующий раз товар добавится сам, с обеими ценами. Запомненный товар главнее прайса: если такой штрихкод потом придёт в загруженном файле, в телефоне останется ваш товар, а товар из файла не загрузится (список: ⚙ → «Последняя загрузка»).
8. **ПРОДАТЬ:** продажа записана, чек очищен. Ошиблись: **«Вернуть»** в течение 8 секунд.
9. Вкладка **«Сессия»**: «Итого по товарам» — то, что нужно внести в кассу; «По отдельности» — каждый чек, любой можно **отменить**.
10. Когда продажи внесены в кассу магазина, нажмите **«Закрыть сессию»**. Новые продажи пойдут в новую сессию, и ничего не задвоится.
11. Если не нажали, сессия **закроется сама в 23:59** (по часам телефона), и её продажи будут считаться внесёнными. Продажи после 23:59 пойдут в новую сессию.
12. Вкладка **«История»**: закрытые сессии хранятся **90 дней**, внутри можно посмотреть каждую продажу.
13. Вкладка **«Отчёты»**: выберите период («Сегодня», «Вчера», «7 дней», «Месяц» или «Период» с двумя датами). Сверху **Итоги за период**: чеков, сумма продаж, средний чек. Ниже **Продажи по товарам**: по каждому товару сколько продано, себестоимость, розничная сумма и остаток, внизу «Итого». Если у товара нет закупочной цены, в его строке «—», и в итоговую себестоимость он не входит (под таблицей написано, сколько таких товаров). Если у товара нет остатка, в столбце «Остаток» тоже «—». Минусовой остаток показан красным. Отменённые продажи в отчёты не входят.
14. **Изменить цену или остаток товара:** вкладка **«Отчёты»** → переключатель **«Товары: цены и остаток»**. Найдите товар: впишите часть названия, штрихкод или его последние цифры, либо нажмите **📷** и наведите камеру на штрихкод (весовая этикетка тоже подойдёт). Нажмите на товар, измените **розничную цену**, **закупочную цену** или **остаток** и нажмите **«Сохранить»**. В таблице продаж можно нажать прямо на строку товара. Как это работает:
    - поле, которое вы оставили как в прайсе или стёрли, правкой не считается;
    - остаток, который вы вписали, считается с этого момента: дальше из него вычитаются продажи в приложении;
    - себестоимость в отчёте берётся по закупочной цене, которая в телефоне сейчас, поэтому исправленная закупочная цена пересчитывает и отчёт по прошлым продажам (розничная сумма прошлых продаж не меняется: она записана в самой продаже);
    - правка остаётся, пока в новом прайсе это значение не изменилось; если изменилось, берётся значение из прайса. Сразу вернуть значения из прайса можно кнопкой **«Вернуть значения из прайса»** в окне товара;
    - товар, внесённый вами вручную, правится так же (и остаток ему можно вписать). Его можно **удалить из телефона** (кнопка внизу окна): прошлые продажи в отчётах останутся, а если такой штрихкод есть в прайсе, вернётся товар из прайса.

**Лучше сделать заранее, пока касса работает:** пройти по весовым товарам и по одному разу навести камеру на этикетку каждого, нажимая «Запомнить». Тогда в аварийный день все весовые товары уже будут узнаваться.

## Важно знать

- **Данные хранятся только в этом телефоне.** Два телефона дают два отдельных журнала. Запомненные номера с весов тоже хранятся на каждом телефоне отдельно. Если очистить данные браузера или удалить приложение, журнал пропадёт. Установленное на главный экран приложение телефон чистит реже.
- Приложение **не фискальное**: это внутренний учёт, а не кассовый чек. Как оформлять продажи при неработающей кассе, уточните у бухгалтера.
- **Закрытие сессии и отчёты идут по часам телефона.** Если на телефоне неверные дата, время или часовой пояс, сессия закроется не вовремя, а продажи попадут не в тот день отчёта.
- **Остаток в приложении приблизительный:** он равен остатку из последнего прайса минус проданное в приложении после загрузки этого прайса (или после того, как вы вписали остаток). Продажи в основной кассе магазина, возвраты и приход он не видит, пока вы не загрузите свежий прайс. Продажи, отменённые в приложении, не вычитаются.
- **Закупочные цены и остатки лежат в телефоне и видны во вкладке «Отчёты» любому, у кого телефон в руках. Менять там цены и остатки тоже может любой:** приложение не защищено паролем.
- Прайс обновляется, только когда приложение открыто и есть интернет. **Жёлтая метка «прайс…» вверху** значит, что прайс не сверялся больше 3 дней.
- Приложение читает только обычные штрихкоды товаров. QR-коды и коды маркировки (Data Matrix) оно не читает специально, чтобы случайно не принять их за товар.
- Хорошее освещение и неподвижная камера читают штрихкод быстрее. Кнопка 🔦 включает фонарик (если телефон это поддерживает).
- Приложение работает на этом адресе и без интернета, но **первый запуск и установка требуют интернет**.
- Разбор Excel-файла происходит один раз при каждом обновлении прайса, а не при сканировании. Моя проверка на тестовом файле в 57 тысяч строк (30 тысяч товаров): около 1 секунды на компьютере и 5–7 секунд, когда процессор намеренно замедлен в 4–6 раз (имитация слабого телефона). На настоящем телефоне я это не проверял. Выгрузка на несколько тысяч строк загружается за доли секунды.

## Если что-то не так

| Что видите | Что делать |
|---|---|
| Камера не включается | Значок замка рядом с адресом → Разрешения → Камера → «Разрешить». Закройте другие приложения, которые используют камеру. Нажмите 📷. |
| «прайс не загружен» | Откройте приложение при включённом интернете, затем ⚙ → «Обновить прайс». Если пишет ошибку, проверьте, что файл называется `prices.xlsx` (маленькими буквами) и лежит рядом с `index.html`. |
| «На сервере нет файла прайса» | На GitHub нет ни `prices.xlsx`, ни `prices.csv` рядом с приложением. Загрузите файл (часть 4) и подождите 2 минуты. |
| Загрузил `prices.xlsx`, а вверху всё ещё «демо-прайс» | Подождите 2 минуты (GitHub публикует не мгновенно), затем ⚙ → «Обновить прайс». Если пишет ошибку, прочитайте её. Проверьте имя файла: не `Prices.xlsx` и не `prices.xlsx.xlsx`. |
| «Файл Excel повреждён или скачан не полностью» | Загрузите выгрузку на GitHub ещё раз. Старый прайс на телефоне при этом цел. |
| «Не найдены столбцы «Наименование» и «Цена»» | В файле нет столбцов с такими названиями. Подходят: Наименование / Номенклатура / Название; Розничная цена / Цена; Штрихкод; Код; Единица измерения / Ед.; PLU. Переименуйте столбец в файле. Закупочная цена как цена не подходит намеренно. |
| «Это старый формат Excel (.xls)» | Откройте файл в Excel и сохраните как «Книга Excel (.xlsx)» или «CSV UTF-8». |
| Обновил файл на GitHub, а на телефоне старый прайс | Подождите 2 минуты, затем ⚙ → «Обновить прайс». |
| «Товара нет в прайсе» на обычный товар | Возможные причины: у товара нет штрихкода в учётной программе; товара нет в выгрузке (например, нулевой остаток); штрихкод в учётной программе записан с ошибкой (смотрите «Последняя загрузка» и список проблем из `prep.html`). |
| Весовая этикетка не узнаётся | Найдите товар по названию и нажмите «Запомнить» (часть 5, пункт 5). Либо заполните в прайсе столбец **PLU** номером товара на весах: тогда запоминать не нужно. |
| Прайс стал вдвое меньше и не обновляется | Это защита: новый файл с меньше чем половиной товаров отклоняется. Проверьте файл. Если так и должно быть, загрузите его вручную: ⚙ → «Загрузить файл прайса». |
| В «Последней загрузке» написано про закупочные цены и остатки | Это справка: закупочные цены и остатки приложение читает для отчётов и хранит на телефоне. Файл на GitHub виден всем, у кого есть адрес. Если это неприемлемо, перейдите на вариант Б без галочек (часть 4). |
| В отчёте по товарам вместо себестоимости «—» | В прайсе нет закупочной цены у этого товара или нет самого столбца (часть 4). Закупочную цену можно вписать в «Товары: цены и остаток» (часть 5, пункт 14): отчёт по прежним продажам пересчитается. |
| В отчёте у товара остаток «—» | В прайсе нет остатка у этого товара (или нет столбца «Остаток»). Впишите остаток в «Товары: цены и остаток»: дальше приложение само вычитает из него продажи. |
| Остаток в отчёте не такой, как в учётной программе | Приложение считает остаток по последнему прайсу минус продажи в приложении. Продажи в основной кассе оно не видит. Обновите прайс (⚙ → «Обновить прайс») или впишите остаток вручную. |
| Товар из нового прайса не появился в телефоне | Скорее всего, ваш товар, внесённый вручную, имеет такой же штрихкод: он главнее, и товар из прайса не загружается. Список: ⚙ → «Последняя загрузка», строка «Не загружено, потому что штрихкод уже внесён вручную». Чтобы взять товар из прайса, удалите свой: «Отчёты» → «Товары: цены и остаток» → найдите → «Удалить товар из телефона». |
| Цена или остаток, которые я исправил, после загрузки прайса стали другими | Правка действует, пока значение в прайсе не изменилось. Если в новом прайсе оно другое, берётся прайс. Исправленные значения помечены «изменено». |
| Отчёт за месяц показывает только последние дни | Приложение хранит продажи 90 дней, а версии до 1.3 хранили 5. Под отчётом написано, с какой даты продажи есть в телефоне. Что телефон уже удалил, вернуть нельзя. |

## Обновление самого приложения

Если файлы приложения заменят новыми (например, при переходе с версии 1.2 на 1.3):

1. Распакуйте архив. На GitHub: **Add file → Upload files** → перетащите файлы из новой папки → **Commit changes**. Файлы с теми же именами заменятся, ничего удалять не нужно. **Не перетаскивайте `prices.csv` из архива, если у вас уже загружен настоящий `prices.csv`:** он учебный и затёр бы ваш. Ваш `prices.xlsx` тоже не трогайте.
2. На телефоне закройте приложение и откройте его **два раза подряд при включённом интернете**: первый раз оно скачивает новую версию, второй раз запускает её. Проверка: **⚙ → строка «Версия»** должна показывать 1.3. После этого побудьте в приложении минуту при включённом интернете: прайс разберётся заново один раз, и в нём появятся закупочные цены и остатки (если они есть в файле).
3. Продажи, чек, запомненные номера, товары, внесённые вручную, ваши правки цен и остатков и загруженный прайс при обновлении сохраняются.
4. Сессия, которая была открыта до обновления, закроется в ближайшие 23:59. Для продаж, сделанных до обновления, себестоимость в отчёте берётся из текущего прайса, а остаток считается от момента, когда прайс разобрался заново (продажи до этого момента из него не вычитаются).
